# ShadowDSP plugins

VST3 plugins built with HISE, one HISE project per plugin. Company "ShadowDSP"; all GPL (see
"Licences").

| Project | Folder | What |
|---|---|---|
| Blackveil | `projects/Blackveil/` | Techno rumble kick generator (an audio effect that takes MIDI); every module is wired, host parameters, KEY and SEND GATE (2026-10-29), RANDOM, presets, GRAIN and BOUNCE (2026-10-30). Read its `CLAUDE.md`, `SPEC.md`, `PROGRESS.md`. |

- **Docs, always (user, 2026-10-31: "from now on update the docs when something changes"):** every
  change updates the docs in the same piece of work, without being asked: a user-facing one (a
  control, a range, a default, a workflow, the look) the manual `docs/<plugin>/` (and its
  screenshots when the window changed), the root `README.md` when a highlight changed, and every change the project's `CLAUDE.md` / `SPEC.md` /
  `PROGRESS.md`. No third-party product names in the manual (see "Licences").

- **`shared/`:** code a second project reuses. `shared/dsp/vital_filters.h` (Vital's filters and
  reverb; generated by `tools/gen_vital_filters.sh`) and `shared/dsp/duskverb.h` (DuskVerb +
  `DuskRooms`; `tools/gen_duskverb.sh`). Each
  generator copies its header into each project that has a copy in `DspNetworks/ThirdParty/src/`
  (HISE compiles only what's in a project). Edit the generator's sources, never a
  copy. Planned: `shared/scripts/` for HISEScript (Theme.js).
- **Git:** see `.gitignore`. Not tracked per project: `Binaries/`, `DspNetworks/Binaries/`,
  `AdditionalSourceCode/nodes/`, `PooledResources/`, `Samples/*.ch1` (encoded from the WAVs: a
  fresh checkout needs the samples encoded before a plugin build), HISE autosaves.

## Adding a project

1. Create `projects/<Name>/` with HISE's subfolders (AdditionalSourceCode, AudioFiles, Binaries,
   DspNetworks, Images, MidiFiles, Presets, SampleMaps, Samples, Scripts, UserPresets,
   XmlPresetBackups) and a `project_info.xml` with its own Name, BundleIdentifier and a unique
   4-letter `PluginCode` (pattern `Abcd`, letters only); copy `user_info.xml` (company).
2. `HISE.exe set_project_folder "-p:<abs path>"`, start HISE, and save once
   (`POST /api/project/save {"format":"xml","filename":"<Name>"}`) to get its preset XML.
3. Its sample link is `%APPDATA%\ShadowDSP\<Product name>\LinkWindows` (points at its `Samples`).

## Environment

- **HISE** (self-built, develop branch v4.9.7, with local patches; see `tools/hise-patches/README.md`):
  `C:\dev\HISE\projects\standalone\Builds\VisualStudio2022\x64\Release\App\HISE.exe`
  - **One project at a time:** HISE works on its "current project folder". Switch with
    `HISE.exe set_project_folder "-p:<abs path to projects/<Name>>"` (HISE shut down), then start it.
    `tools/build_plugin.sh` sets it to the project it builds.
- **Visual Studio 2022 Community.** No VS2026, no Python. Use PowerShell or C# (`Add-Type`) for
  scripting, bash (Git Bash) for the shell scripts.
  - **Trap:** PowerShell 5's `Get-Content -Raw` reads a UTF-8 file without BOM as ANSI, and
    `Set-Content -Encoding utf8` then writes mojibake (‹ › · °) and a BOM. Edit files with the editor
    tools or bash, not a PowerShell read / replace / write.
- **VST3 SDK + tools:** `C:\dev\vst3sdk\build\bin\Release\validator.exe` and `renderhost.exe`
  (source in `tools/renderhost`).
  - `renderhost <plugin.vst3> <out.wav> ["Param Name=normalised" ...]` plays a note and a chord
    through an exported plugin and writes 32-bit float WAV (`tools/Analyze.ps1` reads PCM only).
  - `"~Param"` steps that parameter every 25 ms during the note, like a knob drag, for zipper
    tests: `tools/StepClicks.ps1 -File out.wav` (about 1.0 = smooth).
  - It sends a DAW-like transport (playing, 120 BPM, 4/4). A plugin with an audio input (an effect) gets a
    synthetic kick on every beat as its input. Rebuild it with MSBuild on
    `C:\dev\vst3sdk\build\public.sdk\samples\vst-hosting\renderhost\renderhost.vcxproj` (Release).
- **Installing a plugin:** copy `projects/<P>/Binaries/Bundle/<Name>.vst3` to
  `C:\Program Files\Common Files\VST3\` with `robocopy <bundle> <dest> /E /IS` via
  `Start-Process -Verb RunAs`. **Live must be closed** (it locks the plugin and, through it, the
  project's sample files).
- The user works on Windows, in PhpStorm, and tests in Ableton Live.

## Working loop (no GUI clicking needed)

Run commands from the project folder (`projects/<P>`) unless they say otherwise.
1. Start HISE with its REST API: `HISE.exe start_server` (port 1900), then
   `curl -X POST localhost:1900/api/project/load -d '{"file":"XmlPresetBackups/<Xml>.xml"}' -H "Content-Type: application/json"`.
2. Edit a script, then recompile it: `powershell -File ../../tools/rest.ps1 -ModuleId Interface -File <script file>`.
3. Screenshot: `curl "localhost:1900/api/testing/screenshot?moduleId=Interface&outputPath=<abs path>.png"`.
   - Floating tiles can render wrong after a live recompile; reload the project first.
   - An `/api/testing/e2e` `screenshot` step writes `<id>.png` into the project folder. Delete it.
4. Exercise controls:
   - `POST /api/set_component_value {"moduleId":"Interface","id":"<id>","value":<number>}`.
     The value must be a JSON number: a string (e.g. PowerShell passing `-6` as text) makes the
     handler fail with "Unknown exception in handler".
   - e2e `click` works on panels and buttons; `pixelPosition` {x, y} places it (normalised
     `position` didn't land where expected); e2e drag doesn't move knobs, and it passes no
     modifier keys (shift) on drags.
   - Play / record audio: `POST /api/testing/sequence` (`recordOutput`), measure with `tools/Analyze.ps1`.
   - `/api/repl` evaluates one expression (only the first statement of `a; b`).
   - In PowerShell never name a helper `sv` (or another built-in alias: `set`, `gc`...): the alias
     wins over the function and nothing is sent. Control callbacks run asynchronously: wait ~300 ms
     after `set_component_value` before recording.
5. Save: `POST /api/project/save {"format":"xml","filename":"<Xml>"}`, always the project's own
   XML name. Check the XML afterwards: HISE has crashed on save right after `ui/apply`.
6. Build the plugin: `bash tools/build_plugin.sh <Project>` (from the repository root; about 10 min,
   ends with `BUILD OK`), then install (see "Installing a plugin"). The plugin type (instrument / effect /
   midi) comes from the project's `plugin_type` file, instrument if there is none.
   - **Trap: the export compiles HISE's own copy of the script,
     `Scripts/ScriptProcessors/<Xml>/Interface.js`, not `Scripts/Interface.js`.** HISE writes that copy
     when it compiles the script and saves the project. Before every build: upload the script
     (`rest.ps1`), save, and check the copy matches (`diff`: only the empty callbacks HISE appends
     differ). (Blackveil 2026-10-28: a zoom change
     made with HISE shut down never reached the plugin.)
   - **The Windows installer** (2026-10-31; Inno Setup 6, unsigned for now): after the build,
     `bash tools/build_installer.sh <Project>` -> `projects/<P>/Binaries/Installer/<Name>-<Version>-Setup.exe`
     (`INSTALLER OK`; it warns when `Scripts/Interface.js` is newer than the bundle, i.e. a stale
     build). One script for all projects, `tools/installer/plugin.iss`: the bundle into Common
     Files\VST3 (the old bundle deleted first), `LICENSE` (the repository's, GPL-3.0) and the
     project's `installer/THIRD-PARTY.txt` into Program Files\<Company>\<Name> with the
     uninstaller; AppData is never touched. Name and Version come from `project_info.xml`, Company
     from `user_info.xml` (**bump Version for a release**), the id from `installer/app_id` (a
     GUID per project, **never change it**: it's how a new version replaces the old one). A new
     project needs both files. Inno Setup: `winget install JRSoftware.InnoSetup` (user scope,
     `%LOCALAPPDATA%\Programs\Inno Setup 6`).
   - **A GitHub release** (2026-10-31, first: v0.4.0): `gh release create v<Version> <Setup.exe>
     --repo zvectormusic/blackveil --target main --title "<Name> <Version>" --notes-file <notes>`
     (`gh` from winget GitHub.cli, logged in as zvectormusic; not on Git Bash's PATH until a new
     shell: `%LOCALAPPDATA%\Microsoft\WinGet\Packages\GitHub.cli_*\bin\gh.exe`). The manual's
     getting-started (EN and FR) links `releases/latest`. The repository is public.
7. API docs: `C:\dev\HISE\guidelines\api\rest-api.md` and `C:\dev\HISE\guidelines\style\hisescript.md`.
   - `set_script` wants a `callbacks` object (that's what `rest.ps1` builds).
   - Don't trigger the plugin export through the REST wizard. It crashes HISE.

## C++ nodes (DspNetworks/ThirdParty)

- **After editing a node:**
  1. Save the project, then shut HISE down: `POST /api/shutdown`. The DLL is locked while HISE runs.
  2. `HISE.exe compile_networks -c:Release` (HISE's project folder = this project). This only writes
     the DLL project.
  3. Run `DspNetworks/Binaries/batchCompile.bat`. It writes `<Name>2.dll`-style names when the DLL
     exists: delete the old DLL and rename the new one (HISE shut down).
  4. Restart HISE. The plugin export compiles the nodes in itself.
- **Trap: HISE registers every header in `DspNetworks/ThirdParty` itself as a node** (both
  `compile_networks` and the plugin export, which takes its list from `DspNetworks/Binaries/Source`),
  so a helper header there breaks both builds ("'x' n'est pas membre de 'project'"). Helper headers go
  in `DspNetworks/ThirdParty/src/` (HISE's place for them), included as `"src/x.h"`.
- **Trap: never name a node parameter `Type`, `ID` or `Bypassed`.** HISE saves hardcoded-node
  parameters as XML attributes of the module; one called "Type" overwrote the module's own type and
  the project no longer loaded.
- **Builder:** an `add` and a `set_effect` on the same new module must be separate
  `/api/builder/apply` calls (the batch is validated before it runs). `add` appends to the end of a
  chain (chain 3 = FX); to put a module before others, remove and re-add those.
- New parameters go at the end of a node's parameter list, so saved attribute indexes stay valid.

## HISE traps (each of these bit us once)

- **Removing a component from the script does not delete it.** HISE keeps it in the stored UI data,
  still visible, on top, and catching the mouse. After deleting one: `POST /api/ui/apply
  {"moduleId":"Interface","operations":[{"op":"remove","target":"<id>"}]}`, save, and check the
  project's `XmlPresetBackups/*UIData/*.xml` no longer has it.
- **Stacking order comes from the stored UI data, not the script.** New components are appended on
  top (above preset browsers too). After adding one: remove *all* components with `ui/apply`, then
  recompile, so they're recreated in script order; check with `GET /api/list_components?moduleId=Interface`.
  That list also has the script's look-and-feel objects (`laf`, `fdrLaf`...): leave them out of the
  remove batch, one unknown id fails the whole batch (and nothing is removed).
  **The rebuild resets the stored values** of the removed components (their script defaults come
  back, e.g. Blackveil's duck curve and FILTER TYPE): re-set them, save, and diff the project XML.
  A panel above a control blocks it even with "No Callbacks" (Blackveil: every knob on a node plate
  was unreachable in Live). Test a click on a control that sits on a panel, not only on panels.
- **`g.drawPath(path, area)` scales the path's bounds to fill `area`.** Anchor the corners first with
  `startNewSubPath(0,0)` and `startNewSubPath(w,h)` to draw in absolute coordinates.
- **`var` inside paint and LAF functions is global in HISEScript.** Keep names unique-ish.
- **HISEScript allows 32 `reg` variables per script.** A 33rd fails with a misleading "register
  variable already defined"; use `var`.
- **`.changed()` called from `/api/repl` does not run the control callback.** Use `/api/set_component_value`.
- **The REST server handles one request at a time**: set values before a blocking `recordOutput`.
- **Knob `middlePosition`:** "Linear" knobs keep HISE's 0..1 default middle after min/max change,
  which skews the knob and its host mapping; set it to the centre of the range.
- **Script panels get no mouse-wheel events in stock HISE** (only its own components handle the
  wheel). Our HISE patch (`tools/hise-patches`, 2026-10-31) sends one to a panel set to "All
  Callbacks": `event.mouseWheel` true, `event.wheelDeltaY` (up positive; a Windows notch is about
  0.234), `wheelDeltaX`. Other panels pass the wheel on as before.
- **A component made visible again needs `set("visible", true)` in the script**: the stored UI data
  keeps `visible = false`.
- **A stray `local` statement outside any function (e.g. at the top of an included file) hangs
  HISE's compile, with no error**: every compile, project load and even `diagnose_script` times out,
  and the REST server can stop answering. Force-restart HISE; bisect by loading with the committed
  copy of the file (Blackveil 2026-10-29: a botched perl edit pasted code at the top of Theme.js).
- **HISE reads sample maps (and new image files) only at startup**: restart it after adding them.
- **`Engine.saveUserPreset(file)` writes nothing into a missing folder** (no error): create the
  category folder first. **`Engine.loadUserPreset("Folder/Name")` from the REPL did nothing**; pass
  the File (`FileSystem.getFolder(FileSystem.UserPresets).getChildFile("Folder/Name.preset")`).
- **A plugin extracts its embedded factory presets only into a missing `User Presets` folder**
  unless `HISE_OVERWRITE_OLD_USER_PRESETS=1` (then on every version change): an earlier build that
  shipped none leaves the folder empty for good (Blackveil 2026-10-30).
- **HISEScript's `%` is an integer modulo**: `x % 1.0` is always 0. Take a fraction with
  `x - Math.floor(x)` (Blackveil 2026-10-30: every "random" grain in a display landed in one spot).
- **A plugin parameter's VST3 ID is a hash of its component id** (`ScriptedControlAudioParameter`
  is an `AudioProcessorParameterWithID` named after the component; JUCE's legacy index IDs are
  off): DAW automation follows the id, the list position only orders the DAW's display. Renaming a
  component breaks its automation; moving it doesn't.
- **renderhost applies parameters only after ~1 s** (HISE runs the script callbacks
  asynchronously): measure from 1.5 s on, or the first second (the default sound) dilutes the
  difference.
- **HISE records nothing after Live had the audio device**: restart HISE once Live is closed.
- **HISE applies a synth's own Gain after its FX chain**: an Analyser in the chain doesn't see it.
- **Writing a file from a C++ node:** a script's `setAttribute` on a hardcoded module runs the
  node's `setParameter` synchronously on the calling (message) thread, so a node can write a file
  there and the script can use it right after; `ScriptPanel.startExternalFileDrag(file)` from the
  panel's mouse callback drags it into the DAW (Blackveil's BOUNCE, works in Live).

## Conventions

- HISEScript: `inline function` for control callbacks, `local` inside inline functions,
  `const var` for component references (HISE style guide above).
- **Component IDs, plugin parameter names / ranges, and preset-indexed arrays are
  append-only** once a plugin is in use: presets and DAW sessions depend on them. Each project's
  CLAUDE.md has its parameter contract.

## Licences

ShadowDSP plugins are GPL, so GPL-3.0 DSP (Vital, DuskVerb) is fine; keep each vendored
library's notice. A future closed-source plugin could only use permissively licensed DSP (MIT,
STK-4.3...). Never show third-party product names (Vital, DuskVerb...) in a plugin's UI.
